Catch every error: Flutter, async and platform

Flutter has three places where errors escape. Errors inside the framework (build, layout, gestures) go to FlutterError.onError. Errors that happen outside Flutter code, such as an un-awaited Future that throws, go to PlatformDispatcher.instance.onError. If you set neither, they only print to the console, so you never see them from real users.

Use it for

Every app that ships. Send errors to Firebase Crashlytics, Sentry or similar, so you find crashes before users complain.

Watch out for

Set both handlers at the start of main. try/catch handles an error yourself, so remember to log it too. Replace the red error screen in release builds (ErrorWidget.builder). Upload symbols or source maps, or stack traces are unreadable. Do not send personal data. Check the current package docs for setup.

Example code

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Firebase.initializeApp();

  // 1. errors inside the Flutter framework
  FlutterError.onError = (details) {
    FlutterError.presentError(details);                 // still print in debug
    FirebaseCrashlytics.instance.recordFlutterFatalError(details);
  };

  // 2. errors outside Flutter: un-awaited Futures, isolates, plugins
  PlatformDispatcher.instance.onError = (error, stack) {
    FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
    return true;                                         // handled
  };

  // 3. friendlier screen than the red one in release
  ErrorWidget.builder = (details) => kReleaseMode
      ? const Center(child: Text('Something went wrong'))
      : ErrorWidget(details.exception);

  runApp(const MyApp());
}

// your own catch blocks must report too
try {
  await repo.save(item);
} catch (e, st) {
  FirebaseCrashlytics.instance.recordError(e, st);       // non-fatal
  showError();
}
