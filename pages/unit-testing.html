Testing and quality

Unit tests: a ViewModel with a fake repository

A unit test runs plain Dart code without a screen. You give the class a fake dependency, call a method, and check the result. These tests are fast, so you can write many of them.

Use it for

ViewModels, repositories, parsers, validators and any logic that does not need widgets.

Watch out for

Test behaviour, not the code line by line. Give each test one reason to fail. Use a hand-written fake for simple cases, and mocktail when you need to check which calls were made. Do not use the real network or database in a unit test. Await async code, or the test ends before the result.

Example code

// test/todos_view_model_test.dart
// dev_dependencies: flutter_test (SDK)
import 'package:flutter_test/flutter_test.dart';

class FakeRepo implements TodoRepository {
  FakeRepo({this.items = const [], this.error});
  final List<Todo> items;
  final Exception? error;
  @override
  Future<List<Todo>> todos() async {
    if (error != null) throw error!;
    return items;
  }
}

void main() {
  test('server returns 2 todos', () async {
    final vm = TodosViewModel(FakeRepo(items: [Todo('Buy milk'), Todo('Call mom')]));

    await vm.load();

    expect(vm.state, isA<Data>());
    expect((vm.state as Data).items, hasLength(2));
  });
}

// run:  flutter test
