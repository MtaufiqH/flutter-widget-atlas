Interaction models

Navigator

Navigator keeps a stack of routes. push adds one, pop removes the top and can send a value back. The other methods are shortcuts for rearranging that stack.

Use it for

Moving between screens, returning a result from a picker, clearing history after a sign-in.

Watch out for

A dialog or a bottom sheet is a route too, so an extra pop closes the screen behind it. After awaiting a push, check context.mounted before using the context again.

Things that bite
Using context after awaitmistake-Always check if (!context.mounted) return; after awaiting a push or a dialog.
Dialogs and the back buttonrule-A dialog is a route, so Navigator.pop closes it. Popping twice by mistake closes the screen behind it.
PopScopewidget-Replaces WillPopScope. Use canPop: false with onPopInvokedWithResult to confirm before leaving.
Deep links and the webadvice-go_router or auto_route handle URLs, guards and nesting far better than hand-rolled named routes.

Example code

final result = await Navigator.push(
  context,
  MaterialPageRoute(
    builder: (context) => DetailPage(item: item),
    settings: const RouteSettings(name: '/detail'),
  ),
);
if (!context.mounted) return;
if (result != null) setState(() => selected = result);
