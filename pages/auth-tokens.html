App structure and auth

Tokens: store, refresh and log out

After login the server gives you an access token (short life) and often a refresh token (long life). You send the access token with each request. When it expires, a Dio interceptor uses the refresh token to get a new one and repeats the failed request, so the user never notices.

Use it for

Any app with a login. This builds on the Dio page and the route guard page.

Watch out for

Store tokens in flutter_secure_storage, not SharedPreferences. Refresh once at a time (QueuedInterceptor), or parallel 401s all refresh together. Use a separate Dio for the refresh call, or it loops. If the refresh fails, clear everything and send the user to login. Never log tokens.

Example code

final _store = const FlutterSecureStorage();

class AuthInterceptor extends QueuedInterceptor {   // one request at a time
  AuthInterceptor(this._dio, this._refreshDio);
  final Dio _dio;
  final Dio _refreshDio;   // a plain Dio WITHOUT this interceptor

  @override
  void onRequest(RequestOptions o, RequestInterceptorHandler h) async {
    final token = await _store.read(key: 'access');
    if (token != null) o.headers['Authorization'] = 'Bearer $token';
    h.next(o);
  }

  @override
  void onError(DioException e, ErrorInterceptorHandler h) async {
    if (e.response?.statusCode != 401) return h.next(e);
    try {
      final refresh = await _store.read(key: 'refresh');
      final res = await _refreshDio.post('/auth/refresh', data: {'refresh': refresh});
      await _store.write(key: 'access', value: res.data['access']);
      final retry = await _dio.fetch(e.requestOptions);   // repeat the call
      h.resolve(retry);
    } catch (_) {
      await auth.logout();   // clears storage, the guard sends to /login
      h.next(e);
    }
  }
}
