Permissions and platform

Runtime permissions: ask, explain, recover

Sensitive features (camera, location, notifications) need the user's permission. The status can be not asked, granted, denied, permanently denied, restricted or limited. Each one needs a different reaction from your app.

Use it for

Any feature that uses the camera, microphone, location, contacts, photos or notifications.

Watch out for

Ask at the moment the user needs the feature, not at app start, and explain why first. After a permanent denial you cannot show the system dialog again: send the user to Settings. Always have a path that works without the permission. Each platform needs declarations (AndroidManifest, Info.plist). Some plugins, such as image_picker, ask for you.

Example code

// pubspec: permission_handler
Future<void> openScanner() async {
  var status = await Permission.camera.status;

  if (status.isDenied) {                  // not asked yet, or denied once
    // show your own explanation first, then:
    status = await Permission.camera.request();   // the system dialog
  }

  if (status.isGranted || status.isLimited) {
    openCamera();
  } else if (status.isPermanentlyDenied) {
    // the system dialog will not show again
    await openAppSettings();
  } else if (status.isRestricted) {
    showManualEntry();                    // the user cannot change this
  } else {
    showExplanation();                    // denied: offer to try again
  }
}

// Android: android/app/src/main/AndroidManifest.xml
// <uses-permission android:name="android.permission.CAMERA"/>

// iOS: ios/Runner/Info.plist
// <key>NSCameraUsageDescription</key>
// <string>We use the camera to scan QR codes.</string>

// iOS: Podfile (inside post_install) turns the permission on in the plugin
// 'PERMISSION_CAMERA=1'   (see the permission_handler README)
