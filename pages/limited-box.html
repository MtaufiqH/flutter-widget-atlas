Layout

LimitedBox

LimitedBox applies a maximum only when the incoming constraint is unbounded. If the parent already gives a real limit, it does nothing at all. That is the whole difference from ConstrainedBox.

Use it for

Giving a sensible size to a child that lands in unbounded space, such as inside a horizontal list or a scroll view.

Watch out for

Because it is invisible under bounded constraints, it is easy to think it is broken. Switch the parent in the demo to see when it bites.

The thing people miss
Only in unbounded spacerule-If the parent already gives a real maximum, LimitedBox does nothing at all. That is the whole difference from ConstrainedBox, which always applies.
Where it helpspattern-A child of a horizontal ListView has unbounded width. LimitedBox(maxWidth: 200) stops it stretching forever while still letting a bounded parent decide.
Lists already do thisnote-ListView wraps its children in a LimitedBox internally, which is why an unbounded child inside one usually still renders.
Compared with the neighbours
ConstrainedBoxwidget-Always applies its limits, bounded or not.
UnconstrainedBoxwidget-Removes limits instead of adding them.

Example code

ListView(
  scrollDirection: Axis.horizontal,   // children get unbounded width
  children: [
    LimitedBox(
    maxWidth: 160,   // only used when the width is unbounded
    child: child,
  ),
  ],
)
