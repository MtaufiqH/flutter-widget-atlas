Flavors and release

Fastlane: upload to the stores

Fastlane is a tool that does the boring store steps from the command line: sign, build, and upload to Google Play or TestFlight. You write each job once as a "lane", then run it on your laptop or in GitHub Actions.

Use it for

Send every release to Play internal testing and to TestFlight without clicking through the web pages.

Watch out for

Run flutter build first; Fastlane then uploads the result (iOS needs flutter build ios --no-codesign before build_app). Use an App Store Connect API key and a Play service account instead of your own password, so no two-factor prompt blocks a server. Keep every key in secrets. Use match to share iOS certificates across the team and CI. Fastlane action options change between versions.

Example code

# android/fastlane/Fastfile
default_platform(:android)

platform :android do
  desc "Upload the bundle to the internal testing track"
  lane :beta do
    upload_to_play_store(
      track: "internal",
      aab: "../build/app/outputs/bundle/release/app-release.aab",
      json_key_data: ENV["PLAY_JSON_KEY"],    # the JSON text from a secret
      skip_upload_metadata: true,
      skip_upload_images: true,
      skip_upload_screenshots: true,
    )
  end

  desc "Move the tested build to production"
  lane :promote do
    upload_to_play_store(
      track: "internal", track_promote_to: "production",
      json_key_data: ENV["PLAY_JSON_KEY"], skip_upload_aab: true,
    )
  end
end

# run:   flutter build appbundle --release
#        cd android && bundle exec fastlane beta
