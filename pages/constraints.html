Layout

Layout & constraints

Constraints go down, sizes go up, and the parent decides the position. A parent hands its child a minimum and maximum; the child picks a size inside that range; the parent then places it. Almost every layout surprise comes from this one rule.

Use it for

Understanding why a widget is the size it is, and why setting width sometimes does nothing.

Watch out for

Tight constraints leave the child no choice, so a width on the child is ignored. Unbounded constraints make Expanded and a fraction of the height meaningless.

The one rule
Constraints go down, sizes go uprule-A parent tells its child the minimum and maximum it may be. The child picks a size inside that range. The parent then positions it. A child can never decide where it sits.
BoxConstraints

Building constraints
BoxConstraints(minWidth:, maxWidth:, minHeight:, maxHeight:)constructor-The explicit form.
BoxConstraints.tight(Size)constructor-One exact size.
BoxConstraints.tightFor(width:, height:)constructor-Exact on the axes you give, free on the others.
BoxConstraints.loose(Size)constructor-Anything up to that size.
BoxConstraints.expand(width:, height:)constructor-Fill the space.
constrain(Size) / enforce(other) / copyWith(...) / deflate(insets)method-Clamp a size, combine two sets of constraints, change a few fields, and shrink by padding.
Where the usual errors come from
Unbounded heighterror-A Column inside a SingleChildScrollView gets infinite height, so Expanded has nothing to divide. Use shrinkWrap, a fixed height, or slivers.
Infinite width in a Rowerror-A Row inside a horizontal list has no width limit. Give the child a width or wrap it in Flexible.
Tight constraints ignore your sizesurprise-Inside a tightly constrained parent, a Container with width: 100 is ignored. Wrap it in Center, Align or UnconstrainedBox to loosen them.
Reading them at run time
LayoutBuilderwidget-builder: (context, constraints) gives you the real numbers for this spot in the tree.
MediaQuery.sizeOf(context)function-The whole window, not the space your widget was given. The two are often different.
debugPaintSizeEnabledflag-Draws every box, so you can see who is really constraining whom.
Flutter Inspectortool-The layout explorer shows the constraints and the chosen size for the selected widget.

Example code

Center(
  // loose: min 0, max = what Center was given
  child: Container(width: 120, height: 60),
)

// see the real numbers at any point in the tree
LayoutBuilder(
  builder: (context, constraints) {
    debugPrint('$constraints');
    return child;
  },
)
