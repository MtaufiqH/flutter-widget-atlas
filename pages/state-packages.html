State and architecture

Provider, Riverpod & Bloc

When the built-in tools start to feel repetitive, a state management package helps. Flutter's own architecture guide recommends Provider for dependency injection, and says the choice of state management approach is largely a matter of preference. Riverpod and Bloc are the other widely used options.

Use it for

Sharing and testing state across many screens, injecting repositories and services, and avoiding long chains of constructor parameters.

Watch out for

Pick one approach for the whole project and keep it. Check each package's current docs, because APIs change between major versions. The examples show the same counter in each style and are a starting point.

Properties

Properties4
NameTypeDefaultWhat it does
Provider: context.watch / read / selectextension methods-watch rebuilds, read does not, select rebuilds only for one field.
Riverpod: ref.watch / read / listenWidgetRef methods-Providers are declared outside the widget tree.
Bloc: BlocBuilder / BlocListenerwidgets-Rebuild or react (navigate, show a snack bar) when the state changes.
Choosingadvice-Pick one and use it everywhere. Prefer what your team knows and what is easy to test.

Example code

// pubspec.yaml: provider
ChangeNotifierProvider(
  create: (_) => Counter(),
  child: const MyApp(),
)

// read and rebuild when it changes
Text('${context.watch<Counter>().count}')

// call a method, no rebuild
FilledButton(
  onPressed: () => context.read<Counter>().increment(),
  child: Text('+1'),
)
